# OpenAPI breaking-change detection in pull requests

Every pull request is automatically compared against the base branch's
OpenAPI contract. If the PR introduces a **breaking change** to the API
schema, the `Continuous Integration / OpenAPI Breaking-Change Detection` job
fails with a report of exactly what broke — blocking the merge until the
change is either reverted or explicitly acknowledged via a version bump.

This is enforced by the `openapi-compatibility` job in
`.github/workflows/ci.yml`, which runs
`npm run openapi:check:breaking` (`scripts/check-openapi-breaking-changes.ts`).

## What is compared

The generated `openapi.json` at the repo root on the PR branch against the
same file at the **merge base** with the target branch (`main` by default).
The spec is the one generated by `npm run generate:types` from
`apps/api/src/openapi.config.ts` — see [type-generation.md](./type-generation.md).

CI snapshots the base spec with `git show <merge-base>:openapi.json` into a
temp file and passes it via `--base-path`, so the comparison is between the
exact contents of the two git trees — no regeneration that could mask an
un-committed drift (that case is covered separately by the
`generate:types:check` step).

Diffing against the merge base (rather than the tip of `main`) means a PR is
only ever blamed for changes it actually makes — spec changes that `main`
landed after the branch was cut never fail an unrelated PR.

## Detection layers

### 1. `openapi-diff` (paths, methods, responses, headers)

The [openapi-diff](https://www.npmjs.com/package/openapi-diff) engine
(Atlassian/Microsoft-maintained) classifies changes to `paths`:

Breaking (blocks the merge):
- a path is removed
- a method is removed
- a response body scope is narrowed (fields removed from a response schema)
- a required response header or status code is removed

Non-breaking (reported, allowed):
- new paths, methods, status codes
- widened response bodies (new fields)
- new optional headers

### 2. Component-schema analyzer (`components.schemas`)

`openapi-diff` does **not** classify changes to `components.schemas` at all
(verified against openapi-diff@0.24.1: schema-only diffs produce zero
differences). That is a blind spot for this repo, because no route registers
per-route schemas yet — the generated spec currently consists **only** of
component schemas (see the
[scope note in type-generation.md](./type-generation.md#scope-component-schemas-not-routes)).
The script therefore ships a complementary recursive analyzer that flags:

| Code | Meaning |
| --- | --- |
| `schema.removed` | a component schema was deleted |
| `schema.property.removed` | a property was removed from an object schema (recursive, at any depth) |
| `schema.required.added` | a previously optional property became required |
| `schema.type.changed` | a property's `type` changed (e.g. `string` → `integer`) |
| `schema.enum.value.removed` | an enum value was removed |

Additive changes (new schemas, properties, enum values) are allowed.

## Intentional breaking changes (escape hatch)

Breaking changes fail the check **unless** the PR also bumps the OpenAPI
`info.version` (a semver increase over the base spec). A version bump in the
committed spec is a deliberate, reviewable act.

To ship an intentional breaking change:

1. Bump `version` in `apps/api/src/openapi.config.ts` (`info.version`).
2. Run `npm run generate:types` and commit the regenerated files.
3. Document the migration for API consumers (changelog / docs).

The check then passes with a warning telling reviewers to confirm the
migration is documented. A version *downgrade* or unchanged version never
counts as an acknowledgement.

## Running locally

```bash
# Compare working tree against main (default)
npm run openapi:check:breaking

# Compare against any ref
npx tsx scripts/check-openapi-breaking-changes.ts --base origin/main

# Compare two files (what CI does)
npx tsx scripts/check-openapi-breaking-changes.ts \
  --base-path /tmp/base-openapi.json
```

Exit codes: `0` = no unacknowledged breaking changes (or nothing to compare
against yet, e.g. the base branch has no spec), `1` = breaking changes
detected, `2` = internal error (missing/unparseable spec, diff failure).

## Tests

`scripts/check-openapi-breaking-changes.test.ts` covers the classification
rules (with the real openapi-diff engine, not mocked), the semver
acknowledgement logic, the git plumbing, and the CLI exit-code contract. Run
it with:

```bash
npx vitest run scripts/check-openapi-breaking-changes.test.ts --config scripts/vitest.config.ts
```
